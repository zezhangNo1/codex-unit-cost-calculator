# Codex 单位成本计算器

把 Codex 的**档位倍率 × 区域实付价 × 重置红利**合成一个可比较的数字：**每 1× 额度要花多少人民币**。

同类站点都在回答「什么时候重置」，这个项目回答「这笔钱花得值不值」。

在线访问：<https://7bfb3fccd12942eaa44b74d4a0ae8f6c.app.workbuddy.host>

---

## 首屏只讲一件事

首页第一屏不是免责声明，也不是输入表单，而是**一句结论 + 一根标尺**：

> **Pro 5x 每块钱买到的产能，和 Plus 一模一样**
> 多付的 ¥538 只买到更高的上限，没有买到更便宜的单价。

紧接着是**单位成本标尺** —— 本项目的签名元素：三档落在同一根刻度轴上，Plus 与 Pro 5x 的条形**完全等长**，Pro 20x 恰为一半，另有一条基准虚线穿过。三者关系一眼可见，不需要读数字。

| 档位 | 月付 | 倍率 | 每 1× 额度 | 标记 |
|---|---|---|---|---|
| ChatGPT Plus | ¥134.54 | 1× | **¥134.54** | 基准 |
| Pro 5x | ¥672.68 | 5× | **¥134.54** | 不值 |
| Pro 20x | ¥1345.36 | 20× | **¥67.27** | 最低 |

**这段文案、刻度、条形宽度全部由 `assets/data.js` 推导，不硬编码。** 改数据，结论跟着变（见 `renderHero()`）。

设计原则：**结果区永远和「这个数字有多可信」同等显眼。** 可信度不是脚注，是产品功能。

## 信息架构（对齐参考站，但只借结构不借皮）

页面结构参考 appstoreprice.org —— **顶部标签切换 + 全宽筛选条 + 左排名表 + 右侧栏**。这是同类产品验证过的可扩展骨架：4 个区能看，20 个区也撑得住。

```
┌ 顶栏：品牌 ·［档位对比｜地区对比］· 汇率 · 方法论 ─────────┐
├ 首屏：一句结论 + 单位成本标尺 + 分享图入口 ───────────────┤
├ 筛选：全部配置 ｜ Plus ｜ Pro 5x ｜ Pro 20x ─────────────┤
├──────────────────────────────┬────────────────────────┤
│ 排名表                        │ 最低成本卡（大数 + 归属）│
│ 排名·配置·每 1× 额度·水位·置信度│ 单位成本分布            │
├──────────────────────────────┴────────────────────────┤
├ 口径说明 → 计算器 → 订阅 → 页脚 ────────────────────────┤
```

**但视觉身份另起一套**，不抄它的配色与圆角。理由：如果连皮一起抄，这个站点就只是「同一件商品换了个名字、区域数还只有人家的 1/8」——**必输**。参考站做的是「同一商品跨区比价」，本项目做的是「同一预算跨档位 × 跨区的单位产能」，维度不同，皮也不能共用。

## 视觉系统

方向：**精密计量仪器**。不是随意选的调性 —— 这个产品量的是「每 1× 额度值多少钱」，本质是一把尺子。

| 要素 | 取值 | 理由 |
|---|---|---|
| 底色 | 纸白 `#F4F4F1` + 首屏极淡方格肌理 | 方格是测量基准的表面语言，向下淡出不抢注意力 |
| 分隔 | **发丝线**（`rgba(21,21,26,.085)`）代替投影 | 层级靠留白与字号表达，不靠装饰 |
| 数字 | 展示级数字用**衬线体**（Songti SC / Georgia），表内数字用无衬线等宽位 | 衬线给大数编辑级精度感；表内必须 `tabular-nums` 才能对齐 |
| 布局 | 1180px 双栏，侧栏 sticky | 对齐参考站的可扩展骨架 |

### 颜色语义：一个颜色只准有一个意思

| 颜色 | 唯一含义 | 用在哪 |
|---|---|---|
| 朱砂 `#C0402C` | **最低**（账面） | 排名第一的徽标、数值、水位条、分布图首条 |
| 石绿 `#2B6A4B` | **已核验**（高置信） | 已核验最低徽章、置信度「高」、分布图高置信条 |
| 赭黄 `#8F6410` | **不值** | 被支配配置的标记（如 Pro 5x） |
| 虚线灰 | **未核验**（中/低置信） | 置信度「低」标签用虚线边框 —— **越没核验，标记越不实** |

> 早期版本里红色同时表示「最低价」和「低置信度」，一个颜色两个意思。已拆开：红色只留给「最低」。

### 踩过的坑（都已修，留作记录）

1. **CSS 类名撞车压塌表格。** 排名徽标用了 `.rk`，而排名表是 `<table class="rk">` —— `display:inline-flex` 被套到表格上，`tbody` 直接不渲染。徽标已改名 `.rkb`。**教训：给表格取类名要避开通用短名。**
2. **移动端卡片化规则误伤明细表。** 价格明细表也曾是 `class="rk"`，于是窄屏下表头被 `display:none`、每行被拆成卡片。现明细表独立为 `table.detail`。
3. **脚本重复拼接前缀。** `fxRate` 的外壳在 HTML 里，脚本又拼了一遍 `'1 USD = '`，显示成「1 USD = 1 USD = 6.7268 CNY」。**教训：文案外壳归 HTML，脚本只填值。**
4. **并行编辑同一文件会丢改动。** 同一文件的两次编辑若同时发出，后写的会覆盖先写的。**改同一文件必须串行。**

以上问题都是**靠无头浏览器截图自检**发现的，不是靠读代码发现的。

## 核心洞察

官方只公布**倍率**（Plus 1× / Pro 5x 5× / Pro 20x 20×），从不公布「每月等于多少 credits」的绝对值。一旦把倍率当分母，结论立刻显形：

> **Pro 5x 在单价上被完全支配。** 它的单位成本与 Plus 一模一样，比 Pro 20x 贵一倍。它唯一买到的是「更高的绝对上限」，不是「更便宜的单位产能」。

而重置是**全局事件**，对所有档位等比例生效，因此**不改变排序，只压低绝对水位**。所以它在本项目里只是一个滑块，不是首页的大时钟。

### 一条被数据推翻的旧结论（保留作记录）

早期版本曾写：「升档位」和「换区域」是两条等效路径 —— 依据是官方 Pro 20x 单价 $10.00 与菲区 Plus 的 $9.76 几乎相同。

**这个结论不成立。** 那个 `$9.76` 来自未标口径的二手来源；经核对，菲区 Plus 的真实 iOS 内购价是 **₱999 ≈ ¥106.89（每 1× 额度 ¥106.89）**，而美区 Pro 20x 是 **¥67.27** —— 后者单位成本低约 37%，并非「等效」。**教训：口径不明的数字不能用来下结论。**

## 口径比数字更重要

同一个档位在同一个区域，会因**支付渠道不同**而报出完全不同的价格：Web 官网订阅、iOS App Store 内购、Google Play 内购是三套独立定价。

真实例子：菲律宾区 Plus 曾在中文互联网并流传 `$9.76`、`¥109.82`、`₱1,200` 三个数字，相差近 2 倍。核对后确认：

| 流传数字 | 实际身份 |
|---|---|
| ₱999 ≈ ¥106.89（App Store 菲律宾区，全球最低） | **iOS App Store 内购**口径 |
| ₹ 报 $9.76 的来源 | 疑为 Web 价或未含税 |
| 报 ₱1,200 的来源 | 疑为含税或另一时点 |

**它们不是互相证伪，而是量了三件不同的事。** 所以本项目规定：**缺口径的价格不收录**。

## 本地化决策（面向国内推广）

| 决策 | 取值 | 理由 |
|---|---|---|
| 展示货币 | **人民币（¥）**，单一基准币 | 国内用户无需心算；不做多币种切换，一根尺子量到底 |
| 汇率 | `meta.fx.cny`，手工更新 | 全站**只用同一时点汇率**，避免跨来源比较被汇率差污染 |
| 布局 | **移动端优先** + 桌面双栏 | 国内流量以手机为主；窄屏下排名表整体卡片化（不是横向拖拽），明细表保留表头并横向滚动 |
| 传播形态 | **分享图**（1080×1440 竖版 3:4，含标尺） | 微信外链受限、小红书以图为主 —— 能传播的是图，不是链接 |
| 首屏主角 | **档位结论**（不是区域排行） | 区域排行是参考站已占据的位置；档位单位成本才是本项目的差异化 |
| 置信度呈现 | 与价格**并排成列**，不只放脚注 | 「便宜的往往最没被核验」是本产品的核心矛盾，必须显性化 |

### 分享图

首页「生成结论图」按钮，用原生 `<canvas>` 绘制并下载 PNG，**不引入任何依赖**。图上自动包含：结论标题、三档人民币数字、不值/最优标注、口径说明、汇率时点、免责声明。

实现见 `assets/app.js` 的 `buildShareCanvas()`。注意：中文字体依赖系统字体（`PingFang SC` / `Microsoft YaHei`），服务端渲染场景需自备字体。

## 为什么不用数据库

**刻意不引入数据库，纯静态页面就够。**

| 需求 | 静态方案是否够用 | 说明 |
|---|---|---|
| 计算器 | ✅ 够 | 全部计算在浏览器完成，无服务端状态 |
| 价格与档位数据 | ✅ 够 | 存在 `assets/data.js`，**git 就是数据库** |
| 分享图 | ✅ 够 | 原生 canvas 客户端绘制 |
| 数据更新频率 | ✅ 够 | 区域价格双周更、官方倍率月更、汇率手动更 |
| 价格历史曲线（P1） | ✅ 够 | 给每条价格加 `history: [{date, cny}]` 数组即可 |
| 邮件 / Telegram 订阅 | ⚠️ 不自建 | 交给第三方表单服务，**不自己存用户数据** |
| 用户账号 / 众包提交 | ❌ 不够 | 属于 P2，届时再引入后端 |

**好处：** 零服务器成本、零运维、攻击面几乎为零、可直接免费部署。
**代价：** 做不了个性化 —— 但 MVP 阶段核心价值是**数据可信度**，不是功能丰富度。

订阅表接入方式：

```html
<form class="sub" id="subForm" data-endpoint="https://你的表单服务/xxx">
```

未填 endpoint 时表单明确提示「订阅后端尚未接入」，**不假装提交成功**。

## 目录结构

仓库根目录即项目目录（仓库名 `codex-unit-cost-calculator`）：

```
.
├── index.html          档位对比：首屏结论 + 标尺 + 单位成本排名 + 计算器
├── compare.html        地区对比：各区域实付价排名 + 价格明细与口径
├── method.html         公式、口径说明、官方机制、数据来源、局限性
├── assets/
│   ├── styles.css      共享样式（含移动端断点与卡片化规则）
│   ├── data.js         唯一数据源（手工维护，改这个文件）
│   └── app.js          计算、渲染、分享图（纯前端，无依赖）
└── README.md
```

无构建步骤、无 npm 依赖、无框架。

两个视图由 `<body data-view="unit|price">` 驱动，同一份 `app.js` 渲染两套排名语义：

| data-view | 页面 | 排序依据 | 筛选条 | 侧栏大数 |
|---|---|---|---|---|
| `unit` | index.html | 实际单位成本（含重置红利） | 全部配置 / Plus / Pro 5x / Pro 20x | 最低单位成本 |
| `price` | compare.html | 折人民币实付价 | Plus / Pro 5x / Pro 20x | 最低实付价 |

## 维护数据

只改一个文件：`assets/data.js`。

```js
{
  id: 'PH',
  name: '菲律宾区',
  pending: false,                        // true = 尚未采集，页面显示「数据缺失」
  prices: {
    plus: {
      usd: 15.89,                        // 折美元（计算基准）
      cny: 106.89,                       // 来源直接给出人民币时填此项，优先于 usd × 汇率
      local: '₱999 PHP',                 // 本币标价原文
      caliber: 'iOS App Store 内购',      // 必须写清口径
      source: 'App Store 菲律宾区',
      url: 'https://apps.apple.com/ph/app/id6448311069',
      fetched: '2026-09-16',             // 抓取日期，陈旧度护栏依赖它
      conf: '中',                         // 高 / 中 / 低
      note: '口径与其他来源差异的说明'
    }
  }
}
```

同时记得更新 `meta.fx`（汇率）、`meta.updatedAt`（快照日期）。

**维护铁律：**

1. **抓不到就留空**（不写进 `prices`），页面显示「数据缺失」。**绝不用推算价填补。**
2. **`caliber` 必须写清口径**（Web / iOS App Store / Google Play / 未标注）。读不懂口径的价格就是不可用的价格。
3. **`fetched` 必须真实。** 底部有陈旧度护栏：超过 45 天未更新的条目占比超过 20% 时应视为不可用。
4. **多来源冲突时全部列出**，并在 `note` 里把口径差异说清楚，**不要只说「冲突」**。

## 合规红线（不可逾越）

| 红线 | 规则 |
|---|---|
| 定位 | 只做**信息聚合与对比**，不做攻略与教学 |
| 措辞 | 只陈述各地标价事实，**不给操作路径**（不写「如何换区」「用哪张卡」） |
| 免责 | 每条跨区价格旁必须保留官方机制说明 |
| 广告 | 跨区省钱类内容可能触发广告联盟拒审 → MVP 期不接广告，先跑订阅 |
| 数据 | 不展示任何未经核验的推断价 |

**必须保留的官方机制说明：**

- OpenAI 按**支付方式所属国家**定价，**不是按 IP**
- VPN 换区能看到低价，但**结账会失败**
- 需要真实的当地支付方式，通常要求当地居住身份
- 跨区订阅在 Apple / Google / OpenAI 条款中属灰色地带，**存在封号案例**

## 局限性

- 月费为**估算值**，以付款页实际显示为准
- 倍率是官方倍数，**不是额度绝对值**；本站不换算成 token
- 重置利用率是**用户自评参数**，不是客观事实
- 重置红利对所有档位等比例生效，**不影响排序**
- 折人民币使用**统一时点汇率**；但部分区域价格本身是来源方按各自汇率折算的，跨来源比较仍有系统性误差
- 置信度只衡量「口径与时间戳是否明确」，**不代表该区域可正常订阅**
- 本站**不构成投资或订阅建议**
