# Codex 全球价格对比

一个纯静态的价格对比站：**ChatGPT / Codex 三档订阅在全球 32 个 App Store 地区的实际标价**，以及一个别人不做的东西 —— **每 1× 额度的成本**。

线上地址：`https://7bfb3fccd12942eaa44b74d4a0ae8f6c.app.workbuddy.host`
仓库：`https://github.com/zezhangNo1/codex-unit-cost-calculator`

---

## 首屏只讲一件事

> **只有 Pro 20x 在所有 32 个地区都比 Plus 划算 —— 每 1× 额度的成本稳定是 Plus 的 0.48× ~ 0.52×。
> Pro 5x 则完全看地区：14 个地区它比 Plus 更贵，16 个地区更便宜，2 个地区打平。**

这句话是**由数据算出来的**，不是写死的文案。`relRange()` 现算，数据一变结论跟着变。

### 一条被数据推翻的旧结论（保留作记录）

早期版本的首屏写的是「Pro 5x 每块钱买到的产能和 Plus 一模一样，别买」。

**这是错的。** 它只在**按美元定价的地区**（美国、阿根廷）成立 —— 因为这两个区里 `Pro 5x 价格 ÷ Plus 价格 = 5.002`，正好等于额度倍数比 5。

但在其余地区，Apple 的各区价格档位是独立设定的，这个比值在 **3.65 ~ 6.50** 之间乱跳：

| 地区 | Pro 5x 价格 ÷ Plus 价格 | 折算到每 1× 额度 |
|---|---|---|
| 哥伦比亚 | 3.65× | 比 Plus **便宜** 27% |
| 美国 / 阿根廷 | 5.00× | 持平 |
| 菲律宾 | 6.50× | 比 Plus **贵** 30% |

**教训：拿一个地区的数据去下全站结论，就是把特例当规律。** 重做时改成对 32 个地区逐一计算，结论才站得住。

## 核心洞察（32 区实测）

| 档位 | 每 1× 额度 = 同区 Plus 的 | 全地区一致性 |
|---|---|---|
| Plus | 1.00×（基准） | — |
| Pro 5x | 0.73× ~ 1.30× | ❌ 不稳定，14/32 个地区更贵 |
| Pro 20x | 0.48× ~ 0.52× | ✅ **32/32 个地区都更便宜** |

两个反直觉的发现：

1. **Pro 20x 最贵的地区（哥伦比亚 ¥109.23 / 1×）几乎不比 Plus 最便宜的地区（菲律宾 ¥106.82 / 1×）贵。** 这就是它能全地区胜出的原因。
2. **Pro 5x 的地区价差最小（22%），Plus 和 Pro 20x 都有 51%。** 也就是说 Pro 5x 最不值得为了「换区省钱」而折腾。

## 信息架构

两个视图，共用一个 `assets/app.js`，靠 `<body data-view="unit|price">` 分流。

### 档位对比（`index.html` · `data-view="unit"`）

回答「**买哪一档**」。

```
结论条              一句话 + 由数据现算的区间
三张档位卡          每档：相对同区 Plus 的倍数区间 / 每 1× 额度区间 / 月付区间 / 最低地区
32 区单位成本表     每区一行，三档并列 —— Pro 5x 比同区 Plus 贵的单元格标黄警示
各档位最低/最高地区  含价差
```

### 地区对比（`compare.html` · `data-view="price"`）

回答「**在哪买便宜**」。结构对齐参考站 appstoreprice.org：

```
档位切换            Plus / Pro 5x / Pro 20x
最低价主卡          大数字 + 地区 + 比最高价省 X%
32 区价格排名表      序号 / 地区 / 本币标价 / 折人民币 / 条形
```

### 口径与方法（`method.html` · `data-view="method"`）

算法、数据来源、32 区观测时点、一次真实的数据事故复盘、局限性。

## 视觉系统

**克制优先。** 目标是「精密仪器」而不是「促销海报」。

| 决策 | 理由 |
|---|---|
| 纸白底 `#F7F7F5` + 纯白卡片 + **发丝级描边，零阴影** | 层次由留白和描边建立，不用投影堆出来 |
| **全站只有一个强调色**：朱砂 `#C1362B` = 最低价 | 一个颜色只准有一个意思。第二强调色只给「这里买更贵」的警示（赭黄 `#8A6112`） |
| 数字全部 `tabular-nums` | 表格里的数字必须纵向对齐，否则像没排版 |
| 大数字用紧字距（`letter-spacing:-.045em`） | 大字号不收紧会显得松散 |
| 字重只用 400 / 500 / 600，**不用 700** | 700 在网络字体缺失时会糊成一块 |
| 表格数字列**必须显式写 `.tbl th.r`** | 否则被 `.tbl th{text-align:left}` 的权重盖掉，表头与数字错位（踩过） |

## 数据管道（本项目最关键的部分）

**数据不是手工填的，是生成的。**

```
App Store 各地区 storefront
        │
        │  tools/appstore-prices.mjs
        │  解析页面内嵌的 RSC 载荷（self.__next_f.push），免登录免 token
        ▼
  data/appstore-6448311069.json      原始抓取结果（缓存，可复现）
        │
        │  tools/build-data.mjs
        │  取档位 → 换算 → 组装
        ▼
  assets/data.js                     站点数据（派生物，禁止手工编辑）
```

```bash
node tools/appstore-prices.mjs 6448311069 --json -o data/appstore-6448311069.json
node tools/build-data.mjs          # 更新价格
node tools/build-data.mjs --fetch  # 先重新抓取再生成
```

生成时会自校验：价格条数、有没有 NaN、逐档位打印最低/最高与价差。异常直接 `exit 1`。

### 三条不可违反的数据规则

1. **汇率全站唯一。** 本币 → USD 用来源给的 `priceUsd`，USD → CNY 一律用 `meta.fx.cny`。
   **绝不用来源自己折算的人民币** —— 否则同一个页面里会出现两个汇率，横向比较立刻失真。
2. **只收录一个口径：iOS App Store 内购（月付）。** Web 官网价 / iOS 内购价 / Google Play 内购价是三套独立定价，缺口径的价格不收录。
3. **生成物是派生物。** 改口径改生成器，不手改 `assets/data.js`。

## 一次真实的数据事故（写进方法论的）

早期版本里，阿根廷区 Plus 录的是 `$5.73`、土耳其区录的是 `$14`，来源是 **geopriced.com 和 aisubscriptioncomparison.com —— 都没标价格口径**。

用户看到后质疑「最便宜的不应该是菲律宾吗，阿根廷怎么会这么低」。**用户是对的，我们错了。**

用 32 区实测核对后：

| | 原记录 | 实测 | 真相 |
|---|---|---|---|
| 阿根廷 Plus | `$5.73` | **`USD 19.99`** | 32 区排第 **9**，与美区同价。**阿根廷区直接用美元标价，不随比索汇率打折** |
| 土耳其 Plus | `$14` | **`₺999.99`** | 32 区排第 11 |
| 菲律宾 Plus | `₱999` | `₱999` | ✅ 本来就是对的，32 区第 **1** |

**错的原因不是抓不到数据，是收录了没标口径的二手来源 —— 违反了本站自己定的第 2 条规则。**

这次事故直接催生了三件事：① 建立上面的脚本化数据管道；② 数据文件里加 `dataBatchObservedAt`，把「观测日」和「我们的更新日」分开明示；③ 方法论页专门写了一节复盘。

## 为什么不用数据库

- 数据是**几百条静态记录**，不需要查询引擎。
- **Git 就是版本历史** —— 每次改价都留痕，比数据库的 audit log 更直观、更便宜。
- 没有后端 = 没有攻击面 = 没有运维成本。部署就是推文件。
- 数据管道是脚本化的，更新一次价格 = 跑一条命令 + `git commit`。

订阅功能（邮箱通知）**尚未接入**。静态站不自建账号体系，需要时接第三方表单服务。

## 合规红线（不可逾越）

- **不提供任何跨区订阅的操作路径。** 只陈述各地标价事实。
- **不写教程、不写「如何换区」。** 跨区订阅在 Apple / OpenAI 条款中属灰色地带，存在封号案例。
- **不构成订阅建议。** 每页底部都有免责声明。
- **必须说明官方定价机制**：OpenAI 与 Apple 均按 **支付方式所属国家**定价（不是 IP），VPN 换区能看到低价但结账会失败。

## 局限性

- 价格是**标价事实**，不等于你的实付金额（是否含税、是否叠加平台费各地不同且多数未公开）。
- 各地区 App Store 调价**并不同步**，数据可能已经变化。
- 覆盖的是 App Store 的 **32 个地区，不是全球所有国家**。
- 折人民币只是**一把尺子**，你实际付款用的是本币。
- 官方从不公布「每月等于多少 credits」，因此**本站不换算 token**，只用倍率。
